HotCoco 资源导出工具 0.3.0

双击「HotCoco-资源导出工具.exe」即可使用。适用于 Windows 10/11 x64。
无需安装 Python、Java、.NET 或额外运行库。

工具更新
启动时静默检查本仓库 GitHub Release，也可点击右上角「检查更新」。
发现新版后点击「更新并重启」；工具校验签名和 SHA256，等待旧进程退出后替换原 EXE。
更新保留原文件名，失败时恢复原程序，不改动游戏资源。
查询和下载固定走 gh-proxy.com 官方推荐的国内 IPv4 优选通道，无需 GitHub 令牌或额外配置。
0.2.0 没有更新器，先手动换为 0.3.0 一次，此后即可从工具内更新。

使用流程
1. 推荐把 EXE 放到 .minecraft 同级目录，双击后自动检测游戏包。
   也可以点击「自动检测」，或用「手动选择」选择客户端目录、.minecraft、具体版本文件夹。
   支持把文件夹拖入窗口；手动输入路径后，点击「开始识别」会先检测其中的包。
2. 在「选择包」下拉列表中选择目标版本。只检测到一个包时会自动选中。
   检测到多个包时必须明确选定一个，不会合并多个版本的资源。
   点击「开始识别」，按文件内容查询 Modrinth 和 CurseForge 的具体项目、版本与下载地址。
3. 在列表中勾选要导出的资源。选中一行可以查看识别信息和上游原名。
4. 无法识别的文件须由维护者处理：取消勾选，或选中该行后点击「设为自有」。
   自有标记可以再次点击撤销。程序不会把所有未知文件自动当成自有资源。
5. 填写发布版本，点击「导出清单包」，选择实例目录以外的保存位置。
6. 可使用「下载验证」，选择一个保存位置。程序创建全新的验证目录，重新下载并校验所有选中资源。

文件名规则
你的本地文件名就是清单安装名，也是玩家端部署名，支持中文、空格和括号。
第三方的上游原文件名仅记录为来源信息，不影响部署名。
自有文件随包导出时同样保留目录和文件名。

默认版本隔离布局
HotCoco/
  HotCoco-资源导出工具.exe
  .minecraft/
    versions/
      包A/
        mods/
        resourcepacks/
        shaderpacks/
      包B/
        mods/

选择包A时，只扫描 .minecraft/versions/包A 中的资源。
不会混入包B、.minecraft 根目录的共享资源或其他客户端的文件。
没有资源的版本不会自动回退读取共享 Mod。
识别结果会记录包名、版本隔离布局及能够读取到的 MC／加载器版本。
自动检测优先使用 EXE 所在目录；也支持从工作目录发现游戏包。

导出内容
第三方资源：仅导出项目、版本、下载地址、安装路径与哈希，保持导出包轻量。
明确标记的自有资源：导出清单和实际文件。后续网页发布流程可将这些文件按原名上传 GitHub Release。
仅处理 mods、resourcepacks、shaderpacks 内的 JAR/ZIP；单文件最多 256 MiB。
本版提供资源导出与验证。游戏本体安装、启动器更新和 GitHub 网页发布将在后续接入。

网络设置
代理留空时使用系统网络设置。
若需要明确指定本地代理，可填写 127.0.0.1:7897 或 http://127.0.0.1:7897。
Modrinth 和 CurseForge 为独立识别来源；已有可验证的同一文件来源可在下载时备用。

操作说明
扫描会读取原文件。导出前会再校验内容，文件发生变化时需要重新识别。
下载验证只写入新目录，不覆盖已有游戏实例。
导出包使用新文件名保存，已有导出文件不会直接覆盖。

构建信息
Rust + Windows Win32 原生界面 + WinHTTP + Windows CNG。
使用维护者现有 WSL Rust / MinGW 工具链离线编译，没有额外下载编译链。
源代码：仓库内 src/ 目录。
离线构建脚本：仓库根目录 build-wsl.ps1。
